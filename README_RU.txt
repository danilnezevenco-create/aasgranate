AasGranate: оптимизация дыма RDG-2 / M18 и цветное стекло

Установка
1. Скопируй папку src из этого архива в корень своего проекта aasgranate с заменой совпадающих файлов.
2. Скопировать нужно и Java-файлы, и папку ресурсов shaders: без новых шейдеров этот рендер не работает.
3. Собери свой проект обычной командой gradlew build. Дополнительных зависимостей или изменений build.gradle для этой правки нет.

Это патч исходников для Minecraft 1.20.1 / Forge 47.x. Готового установочного JAR в архиве нет. Присланный текст не содержит полного проекта сборки и бинарных ресурсов, поэтому полная сборка твоего мода здесь не выполнена.

Изменения
- Один клуб дыма: 4 вершины вместо 64. Основное облако: 1040 вместо 16640 вершин. Форма восьмиугольника и заполненное ядро радиусом 60% воспроизводятся шейдером без текстуры дыма.
- Сохраняются 260 клубов, исходные радиус, высота, цвета, плотность, движение, шлейф и продолжительность дыма. Случайные постоянные параметры клубов вычисляются один раз на сущность и хранятся в слабом кэше.
- Все видимые облака сортируются вместе и загружаются в один буфер. Искры используют отдельный буфер и больше не разрывают отрисовку каждого облака.
- Список дымовых сущностей обновляется событиями добавления/удаления. Полный перебор сущностей нужен только при смене мира, а не на каждом кадре.
- Облака вне поля зрения отсекаются. Граница включает сами клубы и оставшийся позади движущейся сущности шлейф.
- Дым делится по глубине прозрачного слоя: сначала часть за стеклом, затем стекло, затем часть перед стеклом. Непрозрачные стены продолжают закрывать дым. Есть отдельная ветка для обычной графики и Fabulous.
- В кадрах без видимого дыма дополнительные проходы и копирование экранных буферов не выполняются. Буферы пересоздаются при смене разрешения и освобождаются при смене/закрытии мира.

Производительность
Число создаваемых вершин уменьшено в 16 раз. Исправление прозрачности использует два прохода одной уже загруженной геометрии, поэтому суммарно получается 2080 обработанных вершин основного облака вместо 16640. Это НЕ означает рост FPS в 8 или 16 раз: остаются стоимость пикселей дыма и полноэкранной композиции. Реальный FPS в Minecraft не измерялся.

Проверки
- Синтаксис Java 17 и изолированная проверка типов всех 9 изменённых/новых Java-классов.
- Проверка типов использовала реальные API Minecraft 1.20.1 и Forge 47.2.0, сверенные сигнатуры Forge-добавлений и временные заглушки только для API двух сущностей и MOD_ID. Это не полная сборка или запуск мода. Временных заглушек в патче нет.
- Обе пары новых GLSL-шейдеров скомпилированы и выполнены в отдельном OpenGL-контексте Mesa llvmpipe.
- 14 сценариев смешивания: дым перед стеклом, за стеклом и по обе стороны, сплошная стена перед дымом, стена за стеклом, дым перед стеной и отсутствие дыма; с обычным порядком глубины и с её очисткой, как в Fabulous.
- 4096 пикселей формы и прозрачности клуба сравнены с интерполяцией исходной геометрии из восьми секторов.

Границы исправления
Это композиция относительно ближайшего слоя прозрачных блоков, а не полноценная попиксельная сортировка любого числа стеклянных поверхностей. Если перед камерой несколько отдельных стёкол, а дым находится между ними, возможны артефакты дальнего стекла.

Перехват ограничен RenderType.translucent() в Forge 1.20.1: два обработчика состояния оборачиваются один раз через ObfuscationReflectionHelper с SRG-именами полей. Исходные обработчики сохраняются. Если сторонний рендерер обходит этот RenderType, оптимизированный дым остаётся, но исправление порядка со стеклом не гарантируется. Oculus, OptiFine, Embeddium и внешние шейдерпаки в Minecraft здесь не проверялись.

Проверить после сборки
Один RDG-2 и один M18 перед цветным стеклом и за ним; стеклянную панель внутри облака; сплошную стену; несколько одновременно активных облаков; вход/выход из облака; дымовой шлейф при броске; изменение размера окна; F3+T; смену мира. Сравнивать FPS нужно в одинаковой сцене, с одинаковыми настройками и количеством дыма.

Состав
src — только необходимые изменения для твоего проекта.
changes.diff — разница с присланными исходниками.
validation.json — результат изолированных проверок, не замер игрового FPS.
